# Проектная работа 5 спринта: PropDevelopment

Аудит безопасности IT-ландшафта строительной компании PropDevelopment.

## Структура

| Папка | Задание | Что внутри |
|---|---|---|
| `Task1` | Проверочный лист по безопасности данных | mindmap в формате draw.io: классификация данных, риски и оценки |
| `Task2` | Проверочный лист для бизнес-систем | таблица проверок с обоснованием выбора разделов |
| `Task3` | Внешние интеграции | диаграмма контекста C4, обновлённая диаграмма контейнеров, требования к интеграции |
| `Task4` | Ролевой доступ к Kubernetes | таблица ролей и скрипты создания пользователей, ролей и привязок |
| `Task5` | Управление трафиком | четыре сервиса и сетевые политики между ними |
| `Task6` | Аудит активности | политика аудита, скрипт разбора журнала, отчёт |
| `Task7` | Безопасность контейнеров | правила допуска подов |

Диаграммы `.drawio` открываются в [draw.io](https://app.diagrams.net): «Файл» → «Открыть».

## Кластер для заданий 4–7

Все задания с кластером рассчитаны на minikube. Один запуск на всё:

```bash
mkdir -p ~/.minikube/files/etc/kubernetes
cp Task6/audit-policy.yaml ~/.minikube/files/etc/kubernetes/audit-policy.yaml

minikube start \
  --driver=podman \
  --cni=calico \
  --extra-config=apiserver.audit-policy-file=/etc/kubernetes/audit-policy.yaml \
  --extra-config=apiserver.audit-log-path=/var/log/audit.log
```

Здесь важны два ключа. `--cni=calico` нужен для задания 5: сетевой модуль по умолчанию
сетевые политики не применяет, и проверка покажет, что запрещённый трафик проходит.
Два ключа `--extra-config` включают аудит для задания 6.
